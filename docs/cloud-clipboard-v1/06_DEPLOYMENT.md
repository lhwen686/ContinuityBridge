# 06 VPS 部署与发布

## 1. 部署前只读核查

实际 OS/架构、可用磁盘/内存、当前用户/sudo、时钟、现有 Docker/Compose、80/443 监听、已有反向代理、现有服务、证书、系统防火墙规则、应用出站网络、源码/镜像获取方式。读取 sudo 权限失败就标明未验证，不索取明文 sudo 密码，不创建 NOPASSWD:ALL。

4 核 8 GB 是用户已给规格，不是资源或性能已验收。服务器可能还承载其他业务；不能为本项目重装、关服务、改变 SSH/代理/DNS/防火墙。对于必要变更先形成文件 diff、端口变化、停机影响与回滚计划，之后才请求一次具体批准。

## 2. 建议部署方式

优先复用已有可信 HTTPS 入口。没有时再提议配置独立域名/子域名及 Caddy 等反向代理。域名、A/AAAA 指向、ACME 端口挑战与可信证书要实际验证；不能用 `curl -k`、不验证 TLS 或自签名警告绕过作为验收。[S18]

Relay 单实例、非 root 容器、只读文件系统、无 docker.sock、无特权、不挂载用户 home。正文只保留内存，限制总在途请求数、超时与内存，例如先设置 512 MiB 容器上限再实测调整；不要把此值当性能结论。因最新项 20 MB 并不意味着处理请求仅占20 MB，要计算并发与多份缓冲。

只将 Relay 应用端口映射到主机 loopback，例如在确认空闲后使用 `127.0.0.1:43117`；对公网只开放经批准的 HTTPS 入口。Docker 发布端口可能绕过 ufw 预期，所以不能仅检查 `ufw status` 就宣称后端私密。[S17]

反向代理不缓存剪贴板，不将请求正文/Authorization 写日志；检查请求缓冲是否落盘，避免破坏“内存暂存”的隐私声明。不要用容器环境输出、命令行参数或 `docker inspect` 全量打印来泄漏 secrets。

## 3. staging 与 production

在同一 VPS 上可以使用两个独立服务实例、域名或明确隔离的入口。它们有不同 token、state、容器/配置。共享机器不等于共享剪贴板槽位。staging 只用合成 fixture。

QA mailbox 是另一个测试专用组件/sidecar，只被 staging 路由到；仅在获准的测试窗口运行。生产镜像/Compose 不能启用 QA 任意控制能力，也不能意外引用测试 token。生产不部署 Mobile MCP、WDA、Xcode 或任意远程 UI 工具。

## 4. 源码、构建、版本

VPS 只部署明确交付的 commit/tag 或由它构建的不可变镜像 digest。最初可以在 VPS 以干净的指定 SHA 构建 Relay 的 Linux 镜像，不要求先接入复杂 CI/GHCR。构建过程与生产服务目录分离；生产不直接跑在开发者不断修改的工作树上。

若采用 CI，Windows-native 测试与 portable Relay 测试分开。CI 能验证构建/API，不能冒充真实 iPhone 或用户桌面剪贴板。不要为了方便向 VPS 复制整个 Windows 工作区、个人 SSH 私钥或 .codex 登录目录。

每次 release manifest 至少有 sourceSha、镜像 digest、平台、协议版本、配置 schema、测试报告索引、前一版本回滚目标；共享清单不得包含真实域名/token/设备识别符。

## 5. P3/P7 的批准模式

P3 首次运行：只读检查 + 生成可审核计划 + 完成镜像/配置的离线可行性准备（不启动公开服务），然后停在 deploy gate。计划用不可歧义 planId 指向精确变更。用户回复例如 `批准执行 staging 计划 <planId>` 后，执行对应计划、健康/鉴权/小 fixture smoke、回滚验证。

P3 升级到新 SHA：复用既有计划形态，但展示本次镜像/SHA、配置差异和回滚目标。只有原授权明确涵盖这次 staging 更新才可继续；否则先申请一次变更批准。

P7 生产：必须有同一候选版本 P6 的证据和可用回滚目标。先给生产变更计划，再接受生产单独批准。不要把“用户让设计”和“用户曾经批准 staging”当生产写入授权。

## 6. 生产后的数据/回滚语义

内存版更新/回滚会清空服务器最新项，这是预先告知的行为。回滚使用上一 digest 和匹配配置，不恢复已过期剪贴板内容。不能把所有正文备份到磁盘来“改善回滚”。

确保 SIGTERM 正常终止连接并释放缓冲；开机拉起策略只针对 Relay。没有发布自动更新系统的需求，Windows v1 可使用可回退的签名/未签名说明明确的便携构建包，不能承诺无 SmartScreen 提醒。
