# 04 iPhone 快捷指令与先行验证

## 1. 最终给用户的操作

电脑 → 手机：电脑 Ctrl+C → 手机运行“CB 取回” → 回到目标 App 粘贴。

手机 → 电脑：手机复制文字/图片 → 运行“CB 发送” → 电脑 Ctrl+V。

“CB 发送”与“CB 取回”是两个产品动作。控制中心、操作按钮、背面轻点属于用户可选入口，不必第一天同时配置。产品成功后关掉 Mac/Codex、拔掉 USB 仍应能工作。

## 2. 配置

使用一个不分享的本地配置快捷指令 `CB 配置` 返回 BaseURL、DeviceToken 和协议版本；部署地址/密钥不进 Git。产品模板内只有配置入口和占位说明。纯快捷指令存储 token 的实际暴露范围见架构第 6 节，不能宣称具备独立 Keychain 保险库。

首次执行读取 capabilities；可按短时间缓存，但服务端限额始终权威。出现 413、版本不匹配或参数更新时刷新。生产与测试配置严格分开，不让 staging token 访问 production。

## 3. “CB 发送”逻辑

1. 在动作开始时读取一次真实 iPhone 剪贴板，存到变量 `OriginalClipboard`；不要让后续通知或文本操作覆盖这个变量。
2. 判断原始内容类型：有真实图片数据优先走图片分支；只有文字走文字分支；仅文件/不支持内容直接提示，不打开文件浏览器寻找替代品。不要无条件“从输入获取图像”后把路径/URL抓取成图片冒充剪贴板图片。
3. 获取 capabilities 和当前 `/v1/clipboard`，保存 `etag`。生成本次 UUID，整个重试过程保留同一 UUID 与正文。
4. 文本分支：直接放进 JSON 字段 `text`，以 POST 调 `/v1/items/text`。不经过显示预览摘要、列表第一个元素或手动拼 JSON。不能以 preview 文本作为实际发送值。
5. 图片分支：尽量使用支持的原始 PNG/JPEG；需要时把静态图片转换为 PNG，检查转换后的编码字节数。不 resize、不有损降质。POST `/v1/items/image`，请求体选择 **File/文件**，值为完整图片数据，Content-Type 与实际编码匹配。
6. 两分支都带 Authorization、Idempotency-Key、If-Match。检查提交返回值/服务器当前项，不把 HTTP 请求未报错等同于完整成功；显示类型、大小和结果，不显示敏感正文。
7. 保留原本本地剪贴板。过大、认证、网络或竞争失败，明确说明该次没有发送成功。

Apple 官方说明 Get Contents of URL 的 POST/PUT/PATCH 可选 JSON/Form/File 请求体，[S8]。这证明可构造请求，不证明某张 20 MB 图片在用户手机上已验证；实际编码对象、HTTP 错误、内存和回前台表现由 P4 检查。

## 4. “CB 取回”逻辑

1. 读取配置并 GET `/v1/clipboard`。`item:null` 时提示“云端没有未过期内容”，原本剪贴板保持不变。
2. 保存 itemId、kind、mime、byteLength、expiresAt 与 etag；下载对应 `/v1/items/{itemId}/content`，请求仍需 Authorization。
3. 确认没有 HTTP 错误、内容类型匹配和未超限。文本必须完整解析为文本；图片必须成为 Shortcuts 里的实际图片对象。需要时明确“从下载数据获取图像”，这里输入已来自受验证的图片接口而非原剪贴板中的 URL。
4. 在复制前重查最新元数据：itemId/etag 未替换且未过期。发生替换或 410 则保留原剪贴板并提示重新取回。避免“先清空剪贴板，再开始下载”。
5. 最后一步才执行“复制到剪贴板”，输入明确绑定到完整文本或实际图片变量，不是 GET 元数据字典、文件名称、路径或通知字符串。
6. 回真实目标 App 粘贴。手机快捷指令图标上的完成提示不是最终验收证据。

Shortcuts 不一定提供可靠的原始 HTTP 状态/头部、字节提取或所有哈希动作，因此 P4 应按真实系统版本探测，并在操作后用受控服务端/客户端测试 oracle 验证。需要调整动作链时仍应维持 API 正确错误语义，不为方便快捷指令而泄漏密钥或取消 TLS 校验。

## 5. 真机技术探路（P4）

先用合成 fixture，不接触用户照片/聊天记录。依次做完整长文本、透明 PNG、小 JPEG、接近 20 MB 的合法 PNG、超限图片。每次记录原始图片类型、编码后长度、上传结果、下载类型、实际粘贴表现；分别区分 byte-equal 传输和 pixel-equal 剪贴板重编码。

Windows 端此时尚未实现时，可以由受控 HTTP 工具写入 staging fixture 验证“云 → iPhone”。要在报告中标注 API fixture，不冒充“Windows 原生剪贴板 → iPhone”通过。

## 6. 创建和交付 .shortcut

优先用现有真实 Shortcuts UI 制作，Mobile MCP 辅助验证；可以在 Mac 制作再通过用户已有同步/分享导入 iPhone，但最终必须在真 iPhone 上执行。允许按当前系统支持的方式导出/签名真实快捷指令文件。macOS `shortcuts` CLI 是 Mac 工具，不是远程运行 iPhone 的命令。[S9]

**禁止将 JSON/plist 文本简单改名为 `.shortcut` 并声称可安装。** 如果无法可靠生成或导出已验证的文件，交付实测动作顺序、变量绑定、设置截图（脱敏）及明确的少量人工创建步骤，标为待完成，不伪造下载产物。

验收后的两个产品 shortcut 模板必须去掉设备 token/私有地址，单独保留配置说明。含 token 的本地副本不得自动分享、推送 Git、录屏或上传日志。

## 7. 自动执行入口与权限

在真 iPhone 上可以打开官方 `shortcuts://run-shortcut?name=...` URL 调用已存在快捷指令，名称需 URL 编码。[S10] 必须确实由手机打开；在 Mac `open` 相同 URL 执行的是 Mac 快捷指令。不要把 token 或实际剪贴板正文放进 URL 查询参数。

手机解锁、开发者信任、Apple 登录、签名授权和首次粘贴权限可能需要用户处理。此类步骤不是测试失败，也不允许由自动化读取密码、绕过锁屏或改安全设置来规避。
