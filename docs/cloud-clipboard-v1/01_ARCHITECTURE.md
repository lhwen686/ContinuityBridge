# 01 架构与产品语义

## 1. 对图二的判断

三台主机的职责分工正确，但应理解为**协作拓扑**，不是三个 Codex 自动共享内存、文件和执行环境。

| 主机 | 开发/测试职责 | 日常使用是否必须在线 |
|---|---|---|
| Windows | 客户端、Win32 剪贴板、托盘、自启动、交互式 Windows 测试；主要代码集成 | 使用电脑剪贴板时需要 |
| Mac mini | Xcode / 已安装 Mobile MCP / WDA；USB iPhone 操作；快捷指令制作与 E2E | 不需要 |
| VPS | Linux Relay、可信 HTTPS、部署、健康、脱敏日志 | 需要 |
| GitHub | 版本化源码、合并与受测提交交接 | 产品运行不需要 |

Codex 的 Local/Remote 指**命令在哪里执行**；Worktree 指**本机 Git 工作树隔离**。两者不能作为三个同级互斥平台。Mac 本地会话已足够；经已验证的远程连接操作 Mac 是可选便利。VPS SSH 会话操作的是 VPS，不是 Windows 的桌面。官方资料见 [S3][S4][S13]。

产品数据路径：Windows 用户会话客户端 ⇄ HTTPS/WSS 443 ⇄ 公网 Relay ⇄ HTTPS 443 ⇄ iPhone 快捷指令。

Mac、USB、WDA、Mobile MCP、Codex、GitHub 不属于这个运行路径。开发用 go-ios USB tunnel 也不等于产品依赖 Tailscale 或局域网。

## 2. 模块选择

沿用现有 C#/.NET 技术栈，不引入第二套后端语言来实现第一版。

- 现有 `ContinuityBridge.Windows`：保留 STA 线程、消息窗口、Win32 生命周期、重试与隐私格式判断，增加真实图片读写。
- 现有 `ContinuityBridge.Core`：保留经过验证的行为，重构文本专用模型、回环和同步状态。不能假定当前 Core 可在 Linux 执行。
- 新增 `ContinuityBridge.Contracts`，目标 `net10.0`：放实际会复用的协议 DTO、版本和序列化约定，不放 WinForms/Win32/Tailscale 类型。
- 新增 `ContinuityBridge.Relay`，目标 `net10.0`、ASP.NET Core Web：Linux 可运行的独立后端，不引用任何 `net10.0-windows` 工程。
- 云同步客户端可以先是 Windows 项目中的清晰组件；只有产生真实复用/测试价值时才拆成额外库。
- 原 `ContinuityBridge.Api` 是 Windows 目标的占位项目，先隔离、标注旧用途；不要把它直接作为生产 Relay。明确无引用后再做单独删除决定。

为跨平台测试建立显式工程列表或 solution filter。Mac/Linux 只构建 Contracts、Relay 和其可移植测试；不以整个 Windows solution 编译失败来判定 Relay 失败。

## 3. latest-only 的准确含义

用户的设备组只有**一个最新项槽位**，不是文本和图片各存一条，也不是每个方向各存一条。最新图片可以替换文本，反之亦然。

一次上传先在有界暂存缓冲中收齐、验证，再在单个原子提交步骤替换槽位。上传失败不破坏旧项；新项未提交前不能被读取。为处理请求必然会存在短暂的在途缓冲，它不构成可查询的历史。

`expiresAt = 服务端成功提交时刻 + 当时生效的 retentionSeconds`，默认 1800 秒。读取、通知重连、重试同一幂等请求不延长 TTL。新用户动作可以生成新 item；同一 requestId 重试不是新动作。调整 TTL 默认只影响新提交项，不追溯续期旧项。

过期时所有正文下载入口立即拒绝，后台清理释放内容引用。客户端在过期前已经获得的内容不会被远程撤销，也不会因此清空本地剪贴板。已经开始的下载可能持有短暂快照：限制传输时长，并在可实现范围内于过期/替换后取消未完成响应；已发出的字节不可召回。

初始实现用一个 Relay 进程、内存最新项、内存有界幂等元数据，不引入 Redis、SQL、对象版本历史。默认重启丢失临时正文；每次启动生成新的 serverEpoch，使旧 revision/重试不会被误当新实例状态。未来由 IClipboardStore 或等价边界接入持久化，不先建一套空存储框架。

“30 分钟过期”是服务访问和应用持有的生命周期保证，不承诺物理介质取证级擦除。内存、swap、崩溃转储、反向代理临时文件、备份与宿主机权限须在威胁说明中单独列出。

## 4. 文本和图片定义

文本是完整 Unicode 纯文本，不是富文本/HTML/网页排版。保留换行、空白、emoji，不做省略号截断、Unicode 归一化或隐式 trim。`U+0000` 等不能可靠映射到 Win32 文本剪贴板的内容要明确拒绝，不能悄悄截断。默认 UTF-8 正文上限 1,000,000 字节。

图片是**剪贴板中的图片数据**。复制资源管理器的 PNG 文件只出现文件列表时，仍属普通文件，不发送。真正图片表示优先于同一剪贴板中的文字替代表示；仅有文件列表、音频、视频、目录、富文本附件不处理。

v1 传输静态 PNG/JPEG。能无修改取得现有编码字节时尽量保留；读取只有 bitmap 的内容时在客户端编码 PNG。HEIC/其他可解码静态图片在客户端转为 PNG。不要为通过大小限制静默缩尺寸、转有损 JPEG 或改变透明度。转换后若超过上限，明确拒绝；这也是 20 MB 验收的一部分。

20 MB 指最终传输图片编码字节 `20_000_000`。不是 JSON/Base64 长度，不是像素展开后的内存大小。另设可配置的 `maxDecodedPixels`，建议起点 64,000,000；客户端必须限制解码内存和恶意尺寸，不能只检查上传字节数。跨平台 Relay 不依赖 Windows `System.Drawing`。

Windows 取回后写入真实图片格式，按目标应用兼容性提供注册 PNG 与 CF_DIBV5/必要的 CF_DIB，保留 alpha；不是把路径、下载链接或 Base64 字符串放进剪贴板。Win32 格式行为依据 [S12]，最终以真实目标应用的粘贴为准。

## 5. 同步与竞争

Windows 是登录用户会话中的托盘进程，不是 Session 0 Windows Service。使用现有 WM_CLIPBOARDUPDATE 机制；HTTP 和图片编码不能堵塞 STA 消息线程。[S12][S13]

每次本地复制生成递增 localGeneration，队列合并为最新候选；至多一个主动上传，旧任务取消后也要靠服务端条件提交防止晚到覆盖。收到云事件仅获取元数据，确认 sourceDeviceId、serverEpoch/revision、itemId、过期和本地 generation，再下载正文；**真正写剪贴板前再次核对**。本地用户在下载期间复制了新内容，旧下载不得覆盖它。

这是最终收敛的跨设备同步，不承诺网络中的所有设备在每一个瞬间完全相同。服务端最后一次检查与客户端落地之间仍有网络竞争窗口；新的通知/状态查询负责收敛，本地 generation 的检查与写入则应在本机串行完成。

云端以成功原子提交的顺序定义最新，不用不可靠的设备墙上时钟排序。所有修改带服务端状态条件，竞争失败有明确错误；新鲜且仍是最新的本地复制最多进行一次基于新状态的自动重试，不能无限互相覆盖。

Windows 自动上传不包含程序启动前已经存在的剪贴板。首次启用同步应告知用户可能写入当前未过期远端项；程序启动时可取回该远端项，但来自本设备的旧项不重复应用，本地启动后新复制的 generation 优先保护。已收到远端并写回的内容用操作标记和受限去重抑制回环，不再上传。不能把“相同 SHA 永远不发送”当去重，否则云项过期后用户重新复制同一内容可能永远传不出去。

离线时仅在本机内存保留最新候选及其当时已知云状态；恢复后先读取云状态。仅在原状态未变、候选仍足够新且未被用户新动作替代时尝试；发生状态冲突就丢弃自动补传并在托盘说明，不无条件覆盖别人更新的内容。本地较新操作仍待处理时，不用恢复时拉取的旧云项覆盖本地；后续新的远端提交再按正常规则接收。

WSS 只发小型“状态有变化”提示。没有历史消息补发假设，断线后 GET 当前状态。WSS 不可用时用 HTTP 元数据轮询作为降级（建议正常降级 5 秒、网络失败指数退避至 60 秒，加抖动）。轮询不用反复下载 20 MB 正文；暂停同步时停止网络活动。

## 6. 安全和日常控制

所有产品接口使用可信 HTTPS，Windows 与 iPhone 分别持有可单独撤销的设备 token（建议使用密码学安全随机生成的至少 32 字节秘密）；服务端由 token 推导真实 sourceDeviceId。不能信任客户端自报的设备身份，也不能把管理员 token 发给客户端。

Windows 用 Credential Manager/等价 OS 保护存储；VPS 只用主机受限 secrets 文件/凭据设施，不写入镜像、Git、命令行或日志。iPhone 纯快捷指令第一版可使用**用户本地填写的配置快捷指令**集中提供设备 token，但这不是受系统 Keychain 强保护的独立保险库。编辑、iCloud 同步与分享快捷指令会扩大暴露面；导出模板必须去掉 token。测试中让用户自行录入，停止截图/录制含密钥的设置页面。

日志只记录状态、耗时、字节计数和匿名化关联 ID；不记录正文、图片、token、请求 Authorization、生产内容 hash。所有正文/元数据响应 `Cache-Control: no-store`，不走公共缓存，不生成公开下载链接。保留托盘暂停、退出、清空云端、网络状态和错误信息。按原代码尊重显式隐私格式；这不能保证识别所有密码或敏感文本，自动剪贴板上传仍须由用户明确启用。

v1 服务器可以读取明文，这属于已接受的安全取舍；“自己的 VPS”不等于云宿主或管理员无法读取。

## 7. 升级边界

Cloudflare：保留 HTTP 契约、能力发现、状态 token、幂等语义、二进制正文与可复用黑盒一致性测试。未来可由 Workers 承接 API、Durable Objects 管理一致状态、R2 承接图片。不能把 20 MB 图片塞进当前 2 MB 上限的 DO 存储值，也不把 eventual-consistent KV 当权威最新状态。[S14][S15]

现有 ASP.NET Core 服务**不能承诺原样作为 Workers 部署**。迁移很可能要重写云端运行时/存储适配，目标是尽量不改客户端契约。30 分钟的对象删除需要应用调度与显式删除；不能假定 R2 生命周期规则提供精确分钟级 TTL。平台限额、CPU、操作费在迁移时重查。[S16]

E2EE：v1 capabilities 只声明 `none`，不伪装已经加密。协议元数据含版本与 cryptoMode；定义未来密文 envelope 的独立演进位置，包含算法版本、keyId、nonce、认证数据约定，敏感 mime/hash 等放入加密内层。v1 服务拒绝未知 cryptoMode；要求 E2EE 的未来客户端拒绝降级。密钥由设备持有而非 VPS。未来 iPhone 可能需要安全加密辅助 App/能力，不承诺当前纯快捷指令完全不改即可获得可靠 E2EE。
